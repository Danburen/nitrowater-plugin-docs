# Main Configuration

The following options live in `config.yml`.

> [!IMPORTANT]
> All configuration files use YAML. Indentation and symbols are significant — keep the existing structure.

> [!TIP]
> After editing, run `/vcx config reload config` to reload only the main config, or `/vcx reload` to reload everything and reschedule tasks.
> A few options (database, language resources) still require a restart.

## Basic switches

```yaml
# Config schema version — used for update/migration checks; normally leave it alone
config-version: 2.1.0

# Master switch: when false the plugin does not initialise (chat, broadcasts, commands)
enable: true
# Debug logging: enable temporarily while troubleshooting
debug: false
# Cross-server chat forwarding: when false messages are not forwarded to other servers
crossing-chat-enable: true
```

- `enable`: controls the **whole plugin**. The plugin is still loaded by Velocity, but it registers no commands and handles no chat or broadcasts.
- `debug`: emits verbose debug logs.
- `crossing-chat-enable`: only controls **cross-server forwarding**. When disabled:
  - messages are no longer sent to other servers;
  - if `log-text.enable` is `true`, the console still logs local chat;
  - mentions, private messages, scheduled broadcasts and entry broadcasts are unaffected.

> [!NOTE]
> VeloChatX only handles **cross-server forwarding**. Chat inside a backend server, and backend-side word filtering, remain the job of that server's chat plugin.

## Update check

```yaml
check-update:
  enable: true
  auto-download: true
```

- `enable`: check GitHub for a new release at startup.
- `auto-download`: download a new release into `plugins/` next to the running jar, named `VeloChatX-<version>.jar`.
  - The running jar is **not** replaced and the proxy is not restarted; replace it manually and restart when convenient.
  - When `false`, the console only prints a notice.

> [!TIP]
> Config "missing keys / outdated version / pending migration" notices are part of startup self-check and are independent of this switch.

## Chat format

Cross-server chat text is generated by resolving placeholders:

```yaml
chat-format: "{channel}{Group}{Server}{Prefix}{Player}{Suffix} §8:§r {Message}"
```

Common placeholders:

| Placeholder | Description |
|---|---|
| `{channel}` | Display name of the channel the player's server belongs to |
| `{Group}` | Player's LuckPerms group |
| `{Prefix}` / `{Suffix}` | Player's prefix / suffix |
| `{Server}` | Display name of the player's server (from `server.list.<id>.display`) |
| `{Player}` | Player name |
| `{Message}` | The chat message |

> [!WARNING]
> `{Server}`, `{Player}` and `{Message}` are **required**.
> If any is missing, the plugin falls back to `{server} {player}: {message}` and logs a warning.

> [!TIP]
> - Placeholders are **case-insensitive**: `{server}` and `{Server}` are equivalent.
> - Most text supports both `§` and `&` colour codes.
> - See the full list in [Placeholder Reference](/en/reference/placeholder).

### Chat text conversion

```yaml
chat-format-model: "none"
```

Controls how text is converted before being forwarded:

| Value | Description | When to use |
|---|---|---|
| `none` | Send raw text without conversion | Vanilla clients; best compatibility (some Fabric clients may misrender) |
| `legacy` | Convert to an Adventure Legacy Component | Recommended; works with most servers and clients |
| `mini-message` | Parse as MiniMessage | When you need rich text (gradients, hover, etc.) |

> [!TIP]
> If unsure, use `legacy`. `mini-message` depends on tag support; invalid tags are shown literally.

## Console chat output

Velocity does not log backend chat by default. To unify chat logs on the proxy:

```yaml
log-text:
  enable: true
  # Convert § colour codes into terminal ANSI colours
  convert: true
```

- `enable`: whether to print cross-server chat to the console.
- `convert`:
  - `true`: render ANSI colours in the console; the log file itself stays free of colour codes;
  - `false`: no conversion, avoiding garbled output in terminals that do not support it.
- This switch also affects how the plugin renders colour codes in other console output; reload after changing it.

> [!TIP]
> With many players, console output costs I/O. Disable `enable` if you do not need unified logs.

## Language and player messages

```yaml
# Server default language: zh / en
locale: zh

# global: use server-language messages (customisable in message.yml)
# locale: use built-in messages in each player's client language (not customisable)
player-locale: global
```

- `locale`: default language for plugin messages and command feedback. Falls back to the JVM language when unset.
- `player-locale`:
  - `global`: use the server `locale`, including custom texts from `message.yml`;
  - `locale`: use built-in texts in the player's client language — good for mixed-language player bases, but those texts cannot be customised.

Message files:

| File | Generated on disk? | Purpose |
|---|---|---|
| `message.yml` | Yes | Player-facing texts: mention, private message, block, banned words |
| `config.yml` | Yes | Main config |
| `broadcast.yml` | Yes | Scheduled and entry broadcasts |
| `system-message/*.yml` | No (bundled in the jar) | Admin texts: command help, status output, binding diagnostics |

> [!NOTE]
> Keys in `message.yml` must not be removed or renamed; values are free to edit.

## Mention titles {#mention-config}

```yaml
mention-show-title:
  enable: true
  time:
    fade-in: 1
    stay: 2
    fade-out: 1
```

When a player uses `/mention`, the target sees a title in the centre of the screen:

- `enable`: whether to show the title.
- `fade-in`: fade-in duration.
- `stay`: fully visible duration.
- `fade-out`: fade-out duration.

> [!TIP]
> Durations are in **seconds** and accept integers; non-integers are rounded.
> A sound (`minecraft:block.note_block.pling`) is also played.
> Main/sub title texts are `mention-title-show-main` / `mention-title-show-sub` in `message.yml`.

## Tab list

VeloChatX can take over the player list, prefix each name with its server, and unify header/footer:

```yaml
tab-list:
  enable: true
  # Dynamic refresh ratio in [0, 1]; 0 keeps a fixed interval
  refresh-ratio: 0.5
  # Base refresh interval in milliseconds; 0 disables periodic refresh
  interval: 1000
  format: "{server}{prefix}{player}{Suffix}"
  header: "Welcome to {proxy} | Current server: {server}"
  footer: "Online §8{online}§r / §8{total_online}§r | Ping: §8{ping}"
```

- `enable`: whether to manage the tab list. When disabled the plugin leaves it untouched.
- `interval`:
  - `> 0`: refresh on that interval;
  - `0`: event-driven — refresh immediately on join/leave/server switch, with a 5-minute full refresh as a fallback.
- `refresh-ratio`: dynamic refresh ratio, clamped to `[0, 1]`:
  - `0`: always use the fixed `interval`;
  - `> 0`: the effective interval grows with the online count:

    ```text
    effective interval = interval × (1 + online / 20 × refresh-ratio)
    ```

    More players means slower refreshes and lower overhead.
- `format`: per-player entry format; supports player and server placeholders.
- `header` / `footer`: tab list top/bottom text; server placeholders only.
  - **Both must be non-empty**; if either is blank, header/footer are not updated.

> [!TIP]
> With many players, increase `interval`, or increase `refresh-ratio` to reduce frequency further.
> Entries and header/footer refresh immediately when players join or leave.

## Banned words

```yaml
ban-words:
  enable: true
  log-to-console: true
  words: "word1,word2"
```

- `enable`: whether to check for banned words.
- `log-to-console`: log the player and message when a word matches.
- `words`: comma-separated list.
  - Matching is **case-insensitive substring** matching (`spam` matches `SPAM` and `spammer`);
  - A matching message is **not forwarded to other servers**; the sender gets a notice;
  - Chat within the sender's own backend is unaffected.

> [!WARNING]
> This only covers cross-server forwarding. Use backend chat plugins for in-server filtering.
